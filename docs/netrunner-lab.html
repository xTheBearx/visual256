Netrunner ID Lab

Development version 0.1. The checksum is mixed through SHA-256 before drawing, so changing a single bit of the input changes the whole badge. The badge bits then pick one of eight themes, one of eight layouts, a portrait, colors, a two-word handle, signal bars, colored character chips and ten detail cells. This page mirrors the Python package in xTheBearx/visual256.

256 subjects

Bits 36–43 pick the portrait from 256 subjects in 23 kinds: 3 android heads, 10 buildings, 10 animals, 10 vehicles, 10 plants, 8 pieces of furniture, 7 foods, 5 pieces of sports equipment, 11 each of musical instruments, computer symbols, large basic shapes and sci-fi insignia, 10 each of weather symbols and space objects, 14 flags, 16 each of holiday symbols and game icons, 12 tools, 11 game pieces, 11 road signs, 12 clothing items, the 32 characters of the badge alphabet on 8 tile styles, and 5 emoji (Noto Emoji, drawn in theme colors). The same four detail fields and symbol mean something that fits each kind; the icon kinds share a fill pattern, a backdrop, an effect and a base. Owl and panda never wear the bow tie, so they stay distinct from cat and fox.

Eight card layouts

Bits 9–11 pick the layout. These previews force each layout onto the same hash so you can compare them. Only the highlighted one is this hash's real badge.

Four detail displays

Bits 12–13 pick how the 10 detail cells are drawn. Each cell is one byte: a colored tile with a symbol (4 + 4 bits), a gem (16 colors × 4 shapes × 4 fills), two hex digits, or an arrow (8 directions × 16 colors × solid or outline).

Eight themes

Bits 0–2 pick the theme: 4 dark and 4 light backgrounds, each a clearly different hue with its own pattern, so the theme alone is recognizable. These previews force each theme onto the same badge bits; only the highlighted one is real.

Sixty-four backgrounds per theme

Bits 3–8 pick the background: 4 directions × 2 tones × 8 hues. The tone is either the theme color fading into the hue, or the hue itself from light to dark. A highlight streak runs along the direction (a ring for radial). Shown in this hash's theme: the 4 directions, the other tone, then the other hues.

Test bench

One-bit change

Flip a single bit of the checksum. Because the badge is drawn from SHA-256 of the whole checksum, about half of all badge bits change, so the two badges look unrelated.

Spoken backup

Not on the badge · a Python output

Standard BIP-39 encoding of the same 256 bits: 24 words, where the last word also carries an 8-bit checksum. Useful for reading a hash over the phone or checking it by hand. The Python package will offer it as an output next to the image. A 512-bit hash gives two lists.

About BIP-39

  • Bitcoin's mnemonic standard. The English list has 2,048 words, so each word carries exactly 11 bits.
  • Every word is 3 to 8 letters, and the first four letters identify a word uniquely, which helps when reading aloud or typing.
  • For 256 bits of data it adds an 8-bit checksum (the first byte of the data's SHA-256), giving 264 bits, or 24 words. The spec notes that this checksum misses 1 in 256 errors.
  • The list used here is the official english.txt, verified by its SHA-256 2f5eed53…3b24dbda. Source: bitcoin/bips, BIP-0039.

Open questions

  • Theme recognition. Are all eight easy to tell apart at true size? Any pair that looks alike weakens the strongest feature.
  • Fingerprint, not encoding. Mixing means the picture can no longer be read back into the checksum. The 24-word backup still can. Is that the right trade?
